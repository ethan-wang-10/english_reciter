# 作文专项第1题：一次有趣的课间游戏

语文站的第1题采用循序练习：先确定主旨，再选择结构和材料，逐步写出句子、重点段和全文，最后修改。选择没有唯一标准答案；系统不按参考范文匹配，不自动打分，不请求AI生成正文。

## 新版九步

1. 主旨立意：选择参考方向，并可在同页改成自己的说法；自己的主旨非空时优先采用。
2. 文章结构：比较总分总、按事情发展顺序、分总等起步安排。说明段落位置和内容组织关系，总分总的中间也能按事情顺序展开。
3. 安排开头：选材料，同时可补充自己的关键词或短句。
4. 中间重点：确定最想展开的一刻，同时补充自己的材料。
5. 安排结尾：选结束、感受或照应材料，也可直接写自己的想法。
6. 细节与句子：动作、对话和反应选项与句子输入同页；关键词选填，自己的句子由学生组织。
7. 写重点段：围绕已选重点和细节展开。确认上一句时可带入学生自己的句子，已有段落保持完整。
8. 连成全文：补上前后内容，形成独立初稿。已有全文不会被后来选择的卡片替换。
9. 点题回看：检查结尾是否回应主旨，必要时返回全文调整。

顶部列出可切换步骤；切换只是查看，不会自动确认。正文区每次只呈现当前问题；同一部分的选项和自由输入并列，说明该写主旨、提纲关键词、句子还是全文。缺少步骤或仍有待复核内容时，完成前提示补齐。

帮助由学生主动打开，先显示与当前问题有关的提示或范文片段，可继续查看完整范文。原创范例逐段标明主旨、结构、细节和点题照应；范文不会自动填入正文。返回帮助前的输入保持完整。

## 修改与成果

九步后继续原有两轮修改：先看内容和顺序，再检查表达、字词与标点。每轮写一句修改理由，或明确勾选检查后不需要修改。最后对比初稿与修改稿，记录收获并保存作品。

完成作品进入语文学科的学习记录，不产生百分制分数。完成稿只读，学生可同题重新练习。

## 保存与兼容

- 新题配置为第2版，新客户端通过 `POST /attempts` 的 `flow_version: 1` 开启九步引导。旧客户端不传此字段时，仍能新建经典六步练习。
- 已有第1版草稿和完成作品保留题目快照与六步操作，不自动迁移或改写正文。旧缓存页面打开新版练习时会提示刷新，避免按旧流程编辑新版作品。
- 草稿自动保存，选择、自己的短句和正文共用同一修订号与事务；版本记录与恢复包含这些内容。
- 家长可查看关联学生的过程和版本，服务器禁止家长写入。
- 并发保存使用严格的 `base_revision` 校验。冲突时保留本机内容，可复制并对照云端稿；明确确认后才放弃未同步内容。
- 修改上游主旨、结构或材料时，相关后续步骤标记待复核，已有文字保持完整。切换参考主旨时，若实际采用的自己的话没有变化，不误标下游。
- 保存并退出会等待最新输入同步。账号切换清空可见私人内容，未同步备份按学生和练习编号隔离。
- 输入建议长度只用于引导，不截短已保存的长稿；服务器按存储边界返回清晰错误并保留原稿。

## 数据与接口

教学内容位于 `subject_content/chinese/writing/lesson-01-game.json`，其中 `guidance` 配置主旨、结构、材料、细节、问题与原创范例。新练习冻结创建时的配置，后续内容更新不改动已有快照。

学生数据位于 `user_data_simple/<学生>/subjects/chinese/writing.sqlite3`。新版 `data.guidance` 保存九步状态和重点段练习；全文使用 `paragraphs.p_full`，内容修改稿与表达修改稿分别使用对应的 `structure_paragraphs.p_full`、`final_paragraphs.p_full`。旧版数据结构继续可读写。空读取不创建数据库。

接口前缀 `/api/subjects/chinese/writing`：

| 接口 | 用途 |
| --- | --- |
| `GET /lessons`、`GET /lessons/<id>` | 题目列表和教学配置 |
| `GET /attempts`、`POST /attempts` | 查看练习，自主新开一次 |
| `GET /attempts/<id>`、`PATCH /attempts/<id>` | 读取和保存草稿 |
| `POST /attempts/<id>/checkpoints` | 保存关键版本 |
| `POST /attempts/<id>/complete` | 完成作品 |
| `GET /attempts/<id>/versions/<version_id>` | 读取历史版本 |
| `POST /attempts/<id>/restore` | 保存当前版本后恢复所选稿 |

新版练习读写及版本接口要求 `X-Writing-Flow: guided-v1`，缺少能力声明返回409 `upgrade_required` 提示刷新；经典练习继续兼容旧请求。保存、检查点、恢复和完成都要求当前 `base_revision`；冲突返回409。兼容请求省略已有 `guidance` 时，服务器保留原辅助状态，不整块擦除。
