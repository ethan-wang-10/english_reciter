# 游戏平衡性 Review 与模拟结论

日期：2026-05-12  
范围：XP 产出、有效打卡、连续打卡、排行榜奖励、月度奖池与 1v1 PK 赌注。

## 目标

1. **低门槛参与**：用户每天答对 5 次即可完成有效打卡，保证轻量用户也有正反馈。
2. **连续打卡优先**：稳定用户应明显优于偶发用户；高强度刷题仍有收益，但不能把差距拉到失落。
3. **控制滚雪球**：排行榜、奖池、赌注不应让头部用户靠 XP 优势持续碾压。
4. **可恢复但不廉价**：补打卡可以救连续火苗，但不计入真实打卡天数、PK 或奖池。

## 主要问题

- 旧规则在每日 300 XP 软上限后仍按 50% 继续给分，90 天模拟中 grinder 的中位 XP 约为 steady 用户的 **4.02 倍**，P90 约 **4.41 倍**。
- weekend_burst 用户虽然有效打卡天数中位数只有 36 天，但旧规则中位 XP 达 steady 用户的 **1.49 倍**，不利于传达“连续打卡更重要”。
- 1v1 PK 只有单局赌注档位，没有本月总风险敞口与安全余量；用户连续接受多局高赌注时，失落感风险偏高。

## 已采用的数值方案

| 模块 | 调整后 | 目的 |
| --- | ---: | --- |
| 每日软上限 | 1000 XP | 提高高强度学习当天的正反馈空间 |
| 软上限后倍率 | 20% | 超过 1000 XP 后仍保留低倍率加练反馈 |
| 每日硬上限 | 无 | 按产品要求不限制单日最高 XP |
| 有效打卡门槛 | 5 次答对 | 维持轻量参与门槛 |
| 今日打卡奖励 | 20 XP + 连续天数 × 1 XP | 给第 5 次答对即时反馈 |
| 打卡连续加成封顶 | 30 天 | 鼓励不断档，但避免长期用户滚雪球 |
| 月目标奖励 | 目标天数 × 30 XP | 保持月度承诺感 |
| 周榜奖励 | 180 / 110 / 70 XP | 降低头部额外注入 |
| 月榜奖励 | 540 / 330 / 220 XP | 降低头部额外注入 |
| PK 安全余量 | 扣费后至少保留 50 XP | 避免用户被扣到接近 0 |
| PK 风险敞口 | 每月最多 3 局带赌注，合计最多 300 XP | 限制连续亏损的挫败感 |

## 模拟方法

脚本：`scripts/balance_simulation.py`

- 周期：90 天
- 随机种子：42
- 用户画像：at_risk、casual、steady、committed、weekend_burst、grinder
- 统计：XP P50/P90、有效打卡天数 P50、最长连续 P50、关键画像比值
- 口径：包含答对 XP、首次有效打卡奖励、月目标奖励、周/月排行榜奖励

运行：

```bash
py -3 scripts/balance_simulation.py
```

- weekend_burst 用户 XP 中位数约为 steady 的 **1.92 倍**，偶发爆刷会明显压过连续轻量学习。

## 仍需线上观察的指标

1. **D1/D7/D30 留存**：验证打卡奖励是否提升连续登录。
2. **有效打卡完成率**：关注答对 4 次即退出的用户比例，必要时加强前端提醒。
3. **每日 XP 分布 P50/P90/P99**：重点观察无硬上限后头部 XP 是否膨胀过快。
4. **补打卡购买率与断签后回流率**：判断补救价格是否合理。
5. **PK 参与率与拒绝率**：观察安全余量和风险上限是否影响挑战热情。

## 置信度说明

该方案已覆盖轻量、稳定、高强度、周末爆发和流失边缘用户的模拟；实现层面可以高置信度交付。由于软上限提高到 1000 XP 且无硬上限，平衡性风险重新集中到头部刷量和周末爆发用户，建议上线后按上方指标做数据回看，而不是承诺绝对 100%。
